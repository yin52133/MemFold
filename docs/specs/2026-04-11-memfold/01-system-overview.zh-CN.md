# 01 System Overview

## 1. MemFold 到底是什么

MemFold 是一个“分层记忆筛选器”，不是一个“全量历史仓库”。

它解决的是这个问题：

同一个 agent 在多个项目、多次 session 中工作时，哪些信息应该默认带着，哪些信息只在需要时再查，哪些信息应该永远不要进入长期层。

## 2. 启动链

对用户来说，MemFold 不是一个需要手动执行的程序。  
对宿主来说，它是一个被静默调用的本地核心。

实际启动链：

```text
宿主启动 session
  -> 宿主插件/hook/skill wrapper 调 memfold load
  -> MemFold 核心读取“启动包”
  -> 返回一小段稳定信息
  -> 宿主静默注入上下文
```

这里用 CLI 而不是常驻服务，是因为第一版更需要：

- 简单稳定
- 易于本地分发
- 易于被不同宿主调用
- 少状态泄漏

所以不要把“CLI”理解成“用户手敲命令入口”，它是核心执行接口。

## 3. 五层结构

### 3.1 启动包

作用：

- 只负责 session 启动时的最小上下文

内容：

- 用户稳定偏好
- 当前项目的稳定约束

特点：

- 它不是长期真相源
- 它是从“长期记忆”编译出来的派生产物

### 3.2 长期记忆

作用：

- 存系统默认相信、默认优先使用的长期信息

应该放：

- 用户稳定偏好
- 项目长期约束
- 经多次验证后仍成立的稳定事实

不应该放：

- 单次推理结果
- 旧任务路径
- 纯背景综述
- 未验证的猜测

### 3.3 工作记录

作用：

- 存当前和近期工作里产生的结构化结果

来源：

- 用户明确表达
- 工具结果
- 代码修改结果
- 测试与验证结果
- 设计决策
- 用户纠正与反馈

这个层的意义是：

- 先记下来
- 不默认载入
- 交给 dreaming 判断能不能进长期记忆

### 3.4 知识库

作用：

- 放背景说明和主题综述

适合放：

- 项目介绍
- 术语解释
- 概念页
- 外部资料总结

它有用，但不是默认决策层。  
它只有在“我要查背景”时才应该靠前。

### 3.5 历史档案

作用：

- 放最深层的追溯材料

意义：

- 当前几层不够时，最后才回溯到这里

它不是“默认全量保存原始全文”的借口。  
对 MemFold 来说，更重要的是“能安全回溯”，而不是“永久保存所有原文”。

## 4. 分析草稿是什么

分析草稿是系统内部的临时推断区。

它可以记录：

- 当前整理过程中的解释
- 检索路径说明
- 暂时性的猜测

但它默认：

- 不进入工作记录
- 不进入长期记忆
- 不进入启动包

它存在的意义只是帮助系统解释自己，不是帮助系统记住自己。

## 5. 为什么是这个层级顺序

默认顺序是：

```text
启动包 -> 长期记忆 -> 工作记录 -> 知识库 -> 历史档案
```

原因：

- `启动包` 最小、最稳，适合一开始就带上
- `长期记忆` 是默认决策层
- `工作记录` 比知识库更接近当前任务事实
- `知识库` 适合解释背景，不适合直接推当前动作
- `历史档案` 成本最高，也最容易带入无关旧信息

## 6. 这套结构到底有什么用

如果没有这五层，记忆系统通常会坏在两个方向：

### 6.1 什么都默认带着走

后果：

- token 膨胀
- 旧错误路径反复注入
- 当前任务被旧背景污染

### 6.2 什么都不敢记

后果：

- 每次都像第一次来这个项目
- 用户长期偏好永远要重复说
- 项目级稳定约束总是丢

MemFold 的结构就是用来把这两个坏方向同时压住。

## 7. 一句话判断标准

如果一条信息：

- 应该默认影响未来行为，去 `长期记忆`
- 只是当前工作的结构化结果，去 `工作记录`
- 只是背景知识，去 `知识库`
- 只是深层追溯材料，去 `历史档案`
- 只是系统自己的推断，去 `分析草稿`

如果这条分类说不清，设计就还不够好。
