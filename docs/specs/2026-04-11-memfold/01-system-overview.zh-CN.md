# 01 System Overview

## 1. MemFold 是什么

MemFold 是一个**分层记忆筛选器**，不是全量历史仓库。

它解决的问题：同一个 agent 在多个项目、多次 session 中工作时，哪些信息应该默认带着，哪些信息只在需要时再查，哪些信息应该永远不进入长期层。

两个核心约束同时成立：
- 默认少载入，避免 token 膨胀和旧路径污染
- 把真正有用的信息留下来，不因为"怕出错"而什么都不记

## 2. 启动链

对用户来说，MemFold 是透明的。对宿主来说，它是被静默调用的本地核心。

```
宿主启动 session
      │
      ▼
宿主插件 / hook / skill wrapper
      │
      ▼  CLI 调用
memfold load --mode normal --scope-type project --scope-id <slug> --intent startup
      │
      ▼
MemFold 核心读取启动包
      │
      ├── memory/user/boot/bundle.md       用户级
      └── memory/projects/<slug>/boot/bundle.md  项目级
      │
      ▼
返回最小稳定信息（JSON）
      │
      ▼
宿主静默注入上下文（用户不可见）
```

CLI 是 MemFold 的核心执行接口，不是用户手敲的工具。选 CLI 而非常驻服务，是因为第一版需要简单稳定、易于本地分发、易于被不同宿主调用、少状态泄漏。

## 3. 五层结构

### 3.1 概览

```
┌──────────────────────────────────────────────────────────┐
│  Layer 1: 启动包                                          │
│  来源：从长期记忆编译出来                                  │
│  特点：最小、最稳，启动时默认注入                          │
│  大小：300~700 tokens（normal 模式）                      │
├──────────────────────────────────────────────────────────┤
│  Layer 2: 长期记忆                                        │
│  来源：dreaming 晋升                                      │
│  特点：默认决策层，存系统相信的稳定事实                    │
├──────────────────────────────────────────────────────────┤
│  Layer 3: 工作记录                                        │
│  来源：当次/近期 session 工作产生                          │
│  特点：先记下来，由 dreaming 判断能否进长期记忆            │
├──────────────────────────────────────────────────────────┤
│  Layer 4: 知识库                                         │
│  来源：背景文档、术语页、项目介绍                          │
│  特点：有用，但不是默认决策层，只在查背景时靠前            │
├──────────────────────────────────────────────────────────┤
│  Layer 5: 历史档案                                        │
│  来源：按日期归档的工作日志                                │
│  特点：追溯用，成本最高，最后才读                          │
└──────────────────────────────────────────────────────────┘
```

### 3.2 启动包

启动包是**编译产物**，不是真相源。它从长期记忆的 `autoload: boot_project` / `boot_user` 条目编译而来。长期记忆变更后必须重编。

### 3.3 长期记忆

应该放：
- 用户稳定偏好
- 项目长期约束
- 经多次验证后仍成立的稳定事实

不应该放：
- 单次推理结果
- 旧任务路径
- 纯背景综述
- 未验证的猜测

### 3.4 工作记录

来源：
- 用户明确表达
- 工具调用结果
- 代码修改结果
- 测试与验证结果
- 设计决策
- 用户纠正与反馈

这层的意义是：先记下来，不默认载入，交给 dreaming 判断能不能进长期记忆。

### 3.5 知识库

放背景说明和主题综述：
- 项目介绍
- 术语解释
- 概念页
- 外部资料总结

只有在"查背景"时才应该靠前，不是默认决策层。

### 3.6 历史档案

按日期归档的工作日志（`memory-YYYY-MM-DD.md`）。每次 session 工作后追加。dreaming 采集信号时优先读这里。

当前几层不够时，最后才回溯到这里。不是"永久保存所有原文"的借口，重要的是"能安全回溯"。

## 4. 分析草稿

分析草稿是系统内部的临时推断区。

可以记录：
- 当前整理过程中的解释
- 检索路径说明
- 暂时性的猜测

规则写死：
- 分析草稿不能进入工作记录
- 分析草稿不能进入长期记忆
- 分析草稿不能进入启动包

原因：如果允许分析草稿晋升，系统会把自己的猜测升成长期事实（自我污染）。

## 5. 层级读取顺序

```
默认顺序：启动包 → 长期记忆 → 工作记录 → 知识库 → 历史档案

知识检索模式：启动包 → 长期记忆 → 知识库 → 历史档案 → 工作记录
```

继续往下读的触发条件：
- 用户显式说"继续上次"
- 用户说"你之前记得"
- 当前上下文有冲突或缺信息
- 用户明确要求回溯对齐

不构成自动扩展理由：
- 只是项目名相同
- 只是主题相似
- 只是实体名相似

## 6. 一句话分类标准

| 信息类型 | 去哪里 |
|---------|--------|
| 应该默认影响未来行为 | 长期记忆 |
| 只是当前工作的结构化结果 | 工作记录 |
| 只是背景知识 | 知识库 |
| 只是深层追溯材料 | 历史档案 |
| 只是系统自己的推断 | 分析草稿 |

如果这条分类说不清，设计就还不够好。
