# 04 Dreaming And Autoresearch

## 1. Dreaming 到底在做什么

Dreaming 不是“模型自由发挥”，也不是“把工作记录全部升成长期记忆”。

它只做一件事：

把 `工作记录` 和 `历史档案摘要` 里的信息，按规则分成四类：

- 保留到长期记忆
- 暂存继续观察
- 隔离等待复核
- 直接丢弃

这四类的区别，必须写清楚，不然 dreaming 就会变成噪音制造器。

## 2. 输入边界

Dreaming 正式消费的输入只有：

- 可晋升的工作记录
- 安全清洗后的历史档案摘要
- 现有长期记忆的比较项

它不能直接消费：

- 分析草稿
- 原始敏感正文
- `sterile` 模式下默认产生的临时记录

## 3. 保留 / 暂存 / 隔离 / 丢弃

### 3.1 直接保留

满足以下任一条件，并且没有冲突或敏感风险时，可直接进入长期记忆：

- 用户明确说“记住这个”
- 这是稳定用户偏好
- 这是稳定项目约束
- 同一条信息跨多个 session 重复出现，且使用后没有被纠正

### 3.2 暂存

满足以下情况时，不进长期记忆，只留在工作记录继续观察：

- 只出现过一次
- 当前看起来有用，但还没跨 session 复现
- 没有足够证据说明它是长期信息

### 3.3 隔离

满足以下情况时，进入隔离区，不允许自动参与后续长期晋升：

- 和现有长期记忆冲突
- 用户明确说“这个不对”
- 证据链自相矛盾
- 敏感性判断不明确

### 3.4 丢弃

以下情况直接丢弃：

- 明显一次性任务状态
- 单次推理过程
- 无法验证的猜测
- 纯分析草稿
- 含敏感原文且无法安全清洗

## 4. Dreaming 的流程

```text
收集候选
  -> 去重
  -> 聚类
  -> 看是否跨 session 复现
  -> 看是否与现有长期记忆冲突
  -> 做出四选一决策
  -> 写解释
  -> 更新长期记忆 / 隔离区 / 丢弃记录
```

关键点不在“模型打几分”，而在：

- 输入是否干净
- 决策是否可解释
- 错误是否能回滚

## 5. 分析草稿为什么不能参与晋升

分析草稿是系统自己的临时解释区。

如果允许它直接进入长期层，就会出现：

```text
系统猜了一次
  -> 自己记成工作记录
  -> 再自己升成长期记忆
```

这就是自我污染。

所以规则必须写死：

- 分析草稿不能直接进工作记录
- 分析草稿不能直接进长期记忆
- 分析草稿只能帮助解释，不帮助记住

## 6. 错误记忆为什么不能只靠 status 挡

如果只是把一条记忆标成 `rejected`，但没有语义墓碑，就会出现：

```text
原错误记忆 A 被 reject
  -> 换个 summary 变成 B
  -> 系统觉得是新东西
  -> 又自动晋升
```

所以需要：

- `claim_fingerprint`
- `tombstones`

这两个东西不是装饰，是防复活的硬约束。

## 7. Dreaming 的能力验收

### 7.1 错误记忆不可复活

失败样例：

- 换 summary 重新晋升
- 换证据重新晋升

通过门槛：

- 被 tombstone 命中的 claim 自动晋升率为 0

### 7.2 Dreaming 不自我污染

失败样例：

- 分析草稿被当成正式记录晋升

通过门槛：

- 纯分析输入的晋升率为 0

### 7.3 敏感信息不入库

失败样例：

- token / cookie / private key 出现在 JSONL、Markdown、SQLite、QMD、benchmark

通过门槛：

- 原文泄漏率为 0

## 8. Autoresearch 的语义

Autoresearch 不是生产功能，它是离线设计验证器。

它不直接改用户记忆，只做一件事：

验证“这套设计规则是不是更好”。

也就是说，它优化的是：

- 什么时候保留
- 什么时候暂存
- 什么时候隔离
- 什么时候丢弃

而不是直接去改生产库。

## 9. 20 轮迭代怎么做

这 20 轮不是 20 次随便改稿，而是 20 次围绕失败样例的定向实验。

### 第一阶段：加载与污染

1. 启动包编译规则
2. `normal/fresh/sterile` 隔离
3. 自动扩展触发条件
4. token 裁剪
5. 错误记忆复活防护

### 第二阶段：索引与回指

6. QMD 文档模型
7. 热路径查询
8. 增量同步
9. 全量重建
10. rename/delete 后回指稳定性

### 第三阶段：跨存储一致性

11. mutation 状态机
12. 崩溃恢复
13. repair 顺序
14. 锁与并发
15. 备份与恢复

### 第四阶段：Dreaming 与安全

16. 工作记录安全闸门
17. 分析草稿隔离
18. 保留精度
19. 删除传播
20. 实验 / 生产隔离

## 10. 每一轮必须产出什么

每一轮都必须交付：

- 一个明确问题
- 一组失败样例
- 一套候选规则
- 一种验收方法
- 通过 / 失败结论

如果某一轮没有失败样例和验收方法，那不叫 autoresearch，只叫继续写说明文。
