# 02 Loading And Retrieval

## 1. 这份文档讲什么

这里只讲运行流，不讲存储实现。

MemFold 有四条核心流：

1. 启动
2. 续做
3. 知识检索
4. 纠错重开

## 2. 启动流

```text
宿主启动 session
  -> 调 memfold load(mode, scope, intent)
  -> MemFold 只读“启动包”
  -> 返回最小稳定信息
  -> 宿主静默注入上下文
```

启动时默认不做的事情：

- 不查工作记录
- 不查知识库
- 不查历史档案
- 不读旧任务推理过程

## 3. 启动包规则

启动包只允许包含两类内容：

- 用户稳定偏好
- 项目稳定约束

默认禁止进入启动包：

- 单次推理
- 旧任务路径
- 低置信工作记录
- candidate/disputed/rejected/quarantined 条目
- 历史档案正文
- 分析草稿

建议预算：

- `normal`：300 到 700 tokens，硬上限 900
- `fresh`：60 到 180 tokens，硬上限 250
- `sterile`：0

## 4. 三种模式

| 模式 | 默认读什么 | 是否允许自动回忆 | 写入后能否自动晋升 |
|------|------------|------------------|--------------------|
| `normal` | 启动包 | 可以，受门控限制 | 可以 |
| `fresh` | 最小启动包 | 不可以，除非显式请求 | 不可以 |
| `sterile` | 不读记忆 | 不可以 | 不可以 |

### 4.1 normal

适合正常工作。  
允许少量自动回忆，但只在有明确理由时发生。

### 4.2 fresh

适合“重新开始，但保留最小用户画像”。  
它的重点不是完全失忆，而是不要把旧项目判断自动拉回来。

### 4.3 sterile

适合“我怀疑旧记忆已经带歪方向”。  
这个模式下，只看当前对话和当前工作区事实。

## 5. 续做流

默认续做顺序：

```text
启动包
  -> 长期记忆
  -> 工作记录
  -> 知识库
  -> 历史档案
```

继续往下读的触发条件只有：

- 用户显式说“继续上次”
- 用户说“你之前记得”
- 当前上下文有冲突或缺信息
- 用户明确要求回溯对齐

以下情况不构成自动扩展理由：

- 只是项目名相同
- 只是主题相似
- 只是实体名相似

## 6. 知识检索流

如果用户要的是背景、术语、综述，而不是直接推进当前任务，那么顺序改成：

```text
启动包
  -> 长期记忆
  -> 知识库
  -> 历史档案
  -> 工作记录
```

原因：

- 知识检索优先背景说明
- 不应被当前工作里的局部噪声主导

## 7. 纠错重开流

当用户明确说：

- “这个不对”
- “忽略上次结论”
- “重新开始”
- “不要沿用之前判断”

系统应该做两件事：

1. 切到 `fresh` 或 `sterile`
2. 把关联长期记忆打到 `disputed` 或 `rejected`

如果只做第一件，不做第二件，错误记忆会在后面继续回来。

## 8. Source Gating

默认规则：

- `normal` / `fresh`
  - 只隐式查长期记忆
  - 工作记录、知识库、历史档案都需要更强触发
- `knowledge lookup`
  - 允许优先查知识库
- `sterile`
  - 不走隐式记忆检索

每条返回结果必须带：

- 来源类型
- 更新时间
- 状态或信任级
- scope
- doc_id
- 指针

结果不能裸塞进 prompt。

## 9. 稳定载入验收

同一快照、同一 `mode / scope / intent` 下，连续两次 `load` 必须得到：

- 相同 item 集合
- 相同顺序
- 相同 token 裁剪结果

最小失败样例：

- mutation 已写状态层，未写内容层
- 内容层已落地，启动包未重编
- `fresh` 错读旧项目记忆
- `sterile` 隐式触发长期记忆检索

如果出现这类失败，系统要么等待稳定点，要么显式降级；不能部分可见。
