# 02 Loading And Retrieval

## 1. 这份文档讲什么

这里只讲运行流，不讲存储实现。

MemFold 有四条核心流：

```
1. 启动流       session 开始时注入最小上下文
2. 续做流       继续上次任务时展开更多层
3. 知识检索流   查背景时优先知识库
4. 纠错重开流   发现旧记忆有误时隔离并重置
```

## 2. 启动流

```
宿主启动 session
      │
      ▼
memfold load(mode, scope, intent=startup)
      │
      ▼
只读启动包：
  memory/user/boot/bundle.md
  memory/projects/<slug>/boot/bundle.md
      │
      ▼
返回最小稳定信息
      │
      ▼
宿主静默注入上下文
```

启动时默认不做的事情：
- 不查工作记录
- 不查知识库
- 不查历史档案
- 不读旧任务推理过程

## 3. 启动包规则

启动包只允许包含两类内容：
- 用户稳定偏好
- 项目稳定约束

默认禁止进入启动包：
- 单次推理
- 旧任务路径
- 低置信工作记录
- `candidate / disputed / rejected / quarantined` 条目
- 历史档案正文
- 分析草稿

Token 预算：

| 模式 | 建议范围 | 硬上限 |
|------|---------|--------|
| `normal` | 300~700 | 900 |
| `fresh` | 60~180 | 250 |
| `sterile` | 0 | 0 |

## 4. 三种启动模式

```
normal ──── 正常工作
  · 读完整启动包
  · 允许有门控的自动回忆
  · 写入后可以晋升到长期记忆

fresh ───── 重新开始，但保留最小用户画像
  · 读最小启动包（只保留用户偏好，不载入旧项目判断）
  · 不做自动回忆，除非显式请求
  · 写入后不晋升

sterile ─── 完全隔离，只看当前对话
  · 不读任何记忆
  · 不做任何自动回忆
  · 写入后不晋升
  · 适合"怀疑旧记忆已带歪方向"
```

## 5. 续做流

```
宿主调 memfold load(intent=continue)
      │
      ▼
启动包（先读）
      │
      ▼ 有触发条件才继续
长期记忆
      │
      ▼ 有触发条件才继续
工作记录
      │
      ▼ 有触发条件才继续
知识库
      │
      ▼ 有触发条件才继续
历史档案
```

继续展开的触发条件：
- 用户显式说"继续上次"
- 用户说"你之前记得"
- 当前上下文有冲突或缺信息
- 用户明确要求回溯对齐

不构成触发的情况：
- 只是项目名相同
- 只是主题相似
- 只是实体名相似

## 6. 知识检索流

查背景、术语、综述时，读取顺序调整为：

```
启动包
  │
  ▼
长期记忆
  │
  ▼
知识库        ← 优先于工作记录
  │
  ▼
历史档案
  │
  ▼
工作记录      ← 最后，避免被局部噪声主导
```

原因：知识检索优先背景说明，不应该被当前工作里的局部噪声主导。

## 7. 纠错重开流

```
用户明确说"这个不对" / "忽略上次结论" / "重新开始"
      │
      ▼
  两件事必须同时做：
      │
      ├── 1. 切换 mode → fresh 或 sterile
      │
      └── 2. 把关联长期记忆打到 disputed 或 rejected
                  │
                  ▼
            写入 tombstone（claim_fingerprint）
```

如果只做第一件（切 mode），不做第二件（标记 + tombstone），错误记忆会在后面的 dreaming 中继续回来。

## 8. Source Gating

每条返回结果必须带：

| 字段 | 含义 |
|------|------|
| `source_type` | 来源层（stable / evidence / wiki / archive） |
| `updated_at` | 更新时间 |
| `status` | 信任级别 |
| `scope` | user / project |
| `doc_id` | 文档标识 |
| `pointer` | 指向真相源的稳定指针 |

结果不能裸塞进 prompt，必须带上述元数据。

默认检索规则：

```
normal / fresh
  · 只隐式查长期记忆
  · 工作记录、知识库、历史档案需要更强触发

knowledge lookup
  · 允许优先查知识库

sterile
  · 不走任何隐式记忆检索
```

## 9. 稳定载入验收

同一快照、同一 `mode / scope / intent` 下，连续两次 `load` 必须得到：
- 相同 item 集合
- 相同顺序
- 相同 token 裁剪结果

最小失败样例：

```
· mutation 已写状态层，未写内容层
· 内容层已落地，启动包未重编
· fresh 错读旧项目记忆
· sterile 隐式触发长期记忆检索
```

如果出现这类失败，系统要么等待稳定点，要么显式降级；不能部分可见。
